# T260 Source / License Audit

This audit covers every dataset the task file names as a candidate for
D1-D3, plus the D4 evaluation source. It documents the exact evidence used
for each admission/rejection decision. Machine-readable summaries are in
`configs/data/posttraining-v1/sources.yaml`.

## D1/D4 -- COCO captions 2017

* **Homepage / terms**: `https://cocodataset.org/#download`,
  `https://cocodataset.org/dataset/termsofuse.htm`.
* The top-level Terms of Use page is a single-page app that AJAX-loads its
  actual text fragment; a naive fetch of the top-level URL returns an
  (almost) empty shell. Fetching the underlying content fragment directly
  confirms: "Annotations ... are licensed under a Creative Commons
  Attribution 4.0 License" and that COCO images "were collected from
  Flickr" and "we do not own the copyright of the images", i.e. images
  carry their original, per-photo Flickr license while the Consortium's
  own annotation/caption text is CC BY 4.0.
* **Admission decision**: Admitted. Manifests only ever reference image
  bytes by their official `train2017/<file_name>` / `val2017/<file_name>`
  relative path (never embed pixels), and only redistribute caption text,
  which is unambiguously CC BY 4.0.
* **train2017 vs val2017**: `val2017` is COCO's own official held-out
  partition, disjoint from `train2017` by construction since the original
  2017 release -- used directly as this task's `evaluation_only` split
  with no additional hashing needed.

## D2 -- LLaVA-Instruct-150K

* **Homepage**: `https://huggingface.co/datasets/liuhaotian/LLaVA-Instruct-150K`.
* HF datasets API: `"gated": false`, `"license": ["cc-by-4.0"]` (no access
  request required).
* **Provenance caveat**: The conversation text was generated by prompting
  GPT-4 with COCO captions/boxes, so besides CC BY 4.0 on the dataset
  release itself, downstream use also falls under OpenAI's Terms of Use
  governing GPT-4-generated content (in particular a
  non-competitive-use restriction on using the output to build a
  competing model). This is a real, if narrow, compliance surface that
  this task does not attempt to adjudicate beyond noting it explicitly
  (recorded in `sources.yaml:license_notes`) -- it does not block
  *admission* for manifest-building/research purposes, but any downstream
  training run should carry this note forward.
* Every referenced image is a COCO `train2017` file (the entry's own `id`
  field is the COCO image id, zero-padded), so image licensing is exactly
  the COCO entry above -- no separate image-license surface for this
  source.
* **Admission decision**: Admitted, with the OpenAI-ToU caveat documented
  rather than silently omitted.

## D3 -- JourneyDB (task's original candidate) -- REJECTED

* **Homepage**: `https://huggingface.co/datasets/JourneyDB/JourneyDB`.
* HF datasets API: `"gated": "auto"`. Attempting to view file listings
  through the standard API redirects to an access-request flow that
  collects a named individual's **First Name, Last Name, Affiliation**,
  plus a usage-agreement checkbox, before granting access. Completing this
  form as an automated agent would mean asserting a real person's identity
  on a legal usage agreement without their explicit, informed
  authorization for this specific act -- out of scope and declined.
* **Terms of Usage** (`https://journeydb.github.io/assets/Terms_of_Usage.html`,
  fetched and read in full): explicitly states users may not "further
  copy, publish or distribute any portion of the JourneyDB dataset,"
  restricts use to a single organization's internal research, and
  separately restricts commercial use and derivative-data exploitation.
  Committing any derived manifest referencing JourneyDB content to a
  shared git repository would violate the no-redistribution clause
  regardless of whether the gated-access form were completed.
* **Admission decision**: **Rejected.** Two independent, each individually
  sufficient, blockers: (1) gated identity-form access this task cannot
  ethically complete, (2) explicit anti-redistribution terms incompatible
  with committing manifests to git. Per the task file's explicit
  allowance to propose a license-compatible alternative when a candidate
  is access/license/provenance/storage-inadmissible, a replacement was
  sought (below) rather than silently substituting or fabricating access.

## D3 -- DiffusionDB 2M (adopted replacement)

* **Homepage**: `https://huggingface.co/datasets/poloclub/diffusiondb`.
* HF datasets API: `"gated": false`, `"license": ["cc0-1.0"]`.
* CC0-1.0 is a public-domain-equivalent dedication: no attribution
  requirement, no redistribution restriction, no commercial-use
  restriction, no derivative-work restriction. This is the strongest
  possible license posture among all candidates considered and fully
  clears every constraint that blocked JourneyDB.
* **File layout note**: DiffusionDB ships two random-sample metadata
  files, `metadata.parquet` (the "2m" random subset, ~2,000,000 rows) and
  `metadata-large.parquet` (a much larger subset). This task fetches only
  the smaller `metadata.parquet` (194,548,652 bytes,
  sha256 `eecd341187bc91c07f5994ad0660d40228ea025616fd57a509bef8323677c68f`),
  consistent with the "bound the pilot subset size" requirement. Actual
  generated images are only addressable inside per-part
  `images/part-NNNNNN.zip` bundles (not individually fetchable without
  downloading a whole part archive) -- this task never bulk-downloads any
  part archive; see `reports/T260/first-report.md` Sec. 4 for the small
  range-fetch verification plan instead.
* **Safety filtering**: DiffusionDB's own recorded `image_nsfw` /
  `prompt_nsfw` scorer columns are used to exclude rows above
  `image_nsfw >= 0.2` or `prompt_nsfw >= 0.5`, and to exclude any row
  missing a score outright (treated as "cannot verify safety", not as
  "assumed safe"). This is a deliberate, documented admission-time
  content-safety gate independent of licensing.
* **Admission decision**: Admitted as the D3 replacement.
